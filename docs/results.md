## Deterministic Cases

| Test | Expected Result | Purpose |
| --- | ---: | --- |
| `all_zeros` | 0 | Reset/baseline behavior |
| `all_ones` | 16 | Basic positive accumulation |
| `increasing` | 1240 | Sum of squares for 0 through 15 |
| `mixed_signs` | -344 | Negative operands and negative result |
| `alternating_signs` | -120 | Alternating positive and negative products |
| `overflow_64bit` | 16000000000000 | 64-bit accumulation beyond 32-bit range |

The overflow stress case uses `A[i] = 1_000_000` and `B[i] = 1_000_000`, producing:

```text
16 * 1_000_000 * 1_000_000 = 16_000_000_000_000
```

That value exceeds signed 32-bit range and fits comfortably in signed 64-bit range.

## Random Tests

The random campaign runs 100 independent tests. Each test generates 16 signed values for `A` and 16 signed values for `B` in the range `[-1000, 1000]`.

For every test:

1. The testbench writes all vector registers through MMIO.
2. It reads back all vector registers to verify the register file.
3. It writes `CTRL.START`.
4. It polls `STATUS.DONE`.
5. It reads `RESULT_LO` and `RESULT_HI`.
6. It compares the hardware result with the software dot-product reference.

The software reference casts operands to `longint signed` before multiplication, so the expected result is computed at 64-bit precision.

## Cycle Behavior

Measured latency is stable across all 106 tests:

| Measurement | Cycles |
| --- | ---: |
| START write issued to DONE observed | 17 |
| MAC iterations | 16 |

Interpretation:

The accelerator accepts a START write, enters `RUN`, performs one signed multiply-accumulate per cycle for 16 elements, latches the result, and reports `DONE`. This simulation validates the MMIO control interface and datapath behavior, but it does not measure FPGA timing, resource utilization, or real CPU bus overhead.
